# Пошаговая инструкция: монитор батареи Dipower DDBGSG51100 на ESP32

От покупки деталей до телеметрии в браузере. Обзор проекта, формат JSON и сведения о BMS —
в [README.md](README.md).

Статус проекта: прошивка собирается, разбор протоколов покрыт тестами, но **на реальной батарее
ещё не проверялась**. Шаги 7–8 — это и есть первая проверка.

---

## Шаг 1. Выберите вариант и купите детали

**Вариант A — из модулей** (дешевле, нужно припаять два резистора):

- [ ] ESP32 DevKit V1, 30 pin — [arduino.ua](https://arduino.ua/prod3990-wi-fi-modyl-devkit-v1-s-esp-32) или любой аналог с [prom.ua](https://prom.ua/Wifi-esp32-wroom.html)
- [ ] Модуль MAX485 — [arduino.ua](https://arduino.ua/prod1343-interfeisnii-modyl-max485-uart-rs485)
- [ ] Резисторы 1 кОм и 2 кОм
- [ ] Провода Dupont «мама-мама», 5–6 штук
- [ ] Патч-корд RJ45 (обычный сетевой кабель)
- [ ] USB-зарядка 5 В / 1 А и USB-кабель под разъём платы

**Вариант B — готовая плата** (без пайки):

- [ ] LilyGO T-CAN485 — [lilygo.cc](https://lilygo.cc/products/t-can485) или [AliExpress](https://www.aliexpress.com/item/1005003624034092.html)
- [ ] Патч-корд RJ45
- [ ] USB-зарядка 5 В / 1 А и кабель USB-C

Понадобятся мультиметр и маленькая отвёртка.

## Шаг 2. Подготовьте кабель RJ45

1. Отрежьте один разъём патч-корда, снимите 3–4 см внешней изоляции.
2. Найдите жилы **оранжевую** и **бело-оранжевую**, зачистите их на 5 мм.
3. Мультиметром в режиме прозвонки убедитесь (контакты считаются слева направо, если держать
   разъём защёлкой вниз и контактами к себе):
   - контакт 1 → бело-оранжевая жила (это **485-B**),
   - контакт 2 → оранжевая жила (это **485-A**).

   Если цвета другие — кабель обжат по T568A; тогда ориентируйтесь на номера контактов, а не на цвет.
4. Остальные шесть жил заизолируйте **каждую отдельно** (на контактах 4 и 5 — шина CAN батареи,
   замыкать их нельзя).

## Шаг 3. Соберите устройство

Схема: [docs/wiring.svg](docs/wiring.svg).

**Вариант A:**

| ESP32 DevKit | MAX485 | Примечание |
|---|---|---|
| VIN (5V) | VCC | |
| GND | GND | |
| GPIO17 | DI | |
| GPIO4 | DE и RE | оба вывода модуля соединить вместе |
| GPIO16 | RO **через делитель** | RO → 1 кОм → GPIO16; от GPIO16 → 2 кОм → GND |

Затем к клеммам модуля: **A** ← оранжевая жила, **B** ← бело-оранжевая.

Делитель обязателен: MAX485 выдаёт на RO 5 В, вход ESP32 рассчитан на 3,3 В.

**Вариант B:** оранжевая жила → клемма **A**, бело-оранжевая → клемма **B**. Больше ничего.

К батарее пока не подключайте.

## Шаг 4. Установите PlatformIO

Нужен Python 3. В терминале:

```bash
pip install platformio
```

Либо поставьте расширение «PlatformIO IDE» в VS Code.

Драйвер USB: у большинства плат стоит CP2102 или CH340. Если после подключения платы в диспетчере
устройств Windows не появился COM-порт — установите драйвер соответствующего чипа.

## Шаг 5. Впишите настройки Wi-Fi

1. Скопируйте `include/secrets.example.h` в `include/secrets.h`.
2. Впишите имя и пароль своей сети (только 2,4 ГГц — ESP32 не работает в 5 ГГц):

   ```c
   #define WIFI_SSID "MyWiFi"
   #define WIFI_PASSWORD "my-wifi-password"
   ```

3. По желанию раскомментируйте строки MQTT и впишите адрес брокера.

`secrets.h` в git не попадает (он в `.gitignore`).

## Шаг 6. Прошейте плату

Подключите плату по USB и выполните в папке проекта.

Вариант A:

```bash
pio run -e esp32dev -t upload
```

Вариант B:

```bash
pio run -e tcan485 -t upload
```

Если прошивка не начинается и висит `Connecting....` — зажмите на плате кнопку **BOOT** и держите,
пока не пойдут проценты.

Откройте журнал:

```bash
pio device monitor
```

Через несколько секунд должна появиться строка вида
`Wi-Fi подключён: http://192.168.1.50/ (http://bms-monitor.local/)`. Запишите адрес.

Пока батарея не подключена, в журнале будет повторяться «BMS не найдена» — это нормально.

<details>
<summary>Альтернатива: готовые образы из папки firmware/ (без PlatformIO)</summary>

В [firmware/](firmware/) лежат собранные образы. В них **не вписан ваш Wi-Fi**, поэтому устройство
через 30 секунд поднимет собственную точку доступа `bms-monitor` (пароль `bms-monitor`), страница
будет на `http://192.168.4.1/`. Этого достаточно, чтобы проверить связь с батареей, но для работы
в домашней сети прошивку нужно собрать самому (шаги 4–6).

```bash
pip install esptool
```

```bash
esptool.py --chip esp32 --baud 460800 write_flash 0x0 firmware/bms-monitor-esp32dev-full.bin
```

Для T-CAN485 — файл `bms-monitor-tcan485-full.bin`.

</details>

## Шаг 7. Подключите к батарее

1. Проверьте DIP-переключатели на батарее: для одиночной батареи DIP1 = ON, остальные OFF (адрес 1).
2. Найдите на нижней панели гнездо с подписью **RS485**. Кабель инвертора не трогайте.
3. Вставьте подготовленный разъём RJ45 в это гнездо.
4. Включите питание устройства (USB-зарядка).

## Шаг 8. Проверьте, что данные идут

1. Откройте в браузере `http://bms-monitor.local/` или адрес из шага 6.
2. В течение минуты статус должен смениться с «поиск BMS…» на «на связи».
3. Сравните процент заряда, напряжение и ток с дисплеем батареи.

Если не заработало — откройте `http://<адрес>/log`:

| Что в журнале | Что делать |
|---|---|
| «BMS не найдена», никаких байтов не получено | Поменяйте местами A и B. Проверьте, что это порт RS485 и BMS включена (горит RUN). В варианте A проверьте провод GPIO4 → DE+RE. |
| «получено N байт, не похоже на ответ» | Перепутаны A/B, либо на этой же шине уже есть ведущий — инвертор (см. ниже). |
| «BMS ответила кодом ошибки» | Связь есть, но команда не поддержана прошивкой BMS. Сохраните журнал — нужно править разбор. |
| Найдена, но цифры не совпадают с дисплеем | Сохраните вывод `/api/telemetry` и журнал — в вашей версии BMS другая раскладка полей. |

**Про инвертор.** На шине RS485 может быть только один ведущий. Если инвертор подключён к батарее
по CAN — конфликта нет. Если по RS485 и свободный порт оказался той же шиной — опросы будут
сбиваться. Тогда переведите связь инвертора на CAN, либо используйте плату T-CAN485 и читайте
батарею по CAN (в прошивке пока не реализовано).

## Шаг 9. Заберите данные на сервер

**HTTP** — опрашивать, когда нужно:

```bash
curl -s http://bms-monitor.local/api/telemetry
```

**MQTT** — если в `secrets.h` задан `MQTT_HOST`, устройство само публикует тот же JSON в топик
`bms/dipower/telemetry` после каждого опроса (раз в 5 секунд), а в `bms/dipower/status` — `online`
или `offline`.

Поля, полезные для уведомлений в Telegram:

| Поле | Смысл |
|---|---|
| `online` | `false` — BMS не отвечает дольше 30 с |
| `soc` | заряд, % |
| `state` | `charging` / `discharging` / `idle` |
| `current`, `power` | плюс — заряд, минус — разряд |
| `eta_min` | минут до полного заряда или до разряда при текущем токе |
| `protections`, `faults`, `warnings` | непустая строка — есть событие |

Полный список полей — в [README.md](README.md#формат-телеметрии).

Совет: закрепите за устройством постоянный IP в настройках роутера (DHCP-резервирование).

## Шаг 10. Обновление прошивки по Wi-Fi (по желанию)

1. В `secrets.h` задайте `#define OTA_PASSWORD "ваш-пароль"` и один раз прошейте по USB.
2. Дальше можно обновлять по сети:

   ```bash
   pio run -e esp32dev -t upload --upload-port bms-monitor.local --upload-flags="--auth=ваш-пароль"
   ```
