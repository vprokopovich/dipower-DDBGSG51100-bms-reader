# BMS-монитор для Dipower DDBGSG51100 (ESP32 + RS485)

ESP32 опрашивает BMS батареи по RS485 и отдаёт телеметрию: процент заряда, напряжение, ток,
мощность, направление (заряд/разряд/покой), остаток ёмкости, напряжения 16 ячеек, температуры,
состояние ключей заряда/разряда, предупреждения и срабатывания защит.

**Пошаговая инструкция по сборке и запуску: [INSTRUCTIONS.md](INSTRUCTIONS.md).** Готовые образы прошивки — в [firmware/](firmware/).

Данные доступны тремя способами:

| Способ | Где |
|---|---|
| Веб-страница | `http://bms-monitor.local/` или `http://<ip>/` |
| JSON по HTTP | `GET http://<ip>/api/telemetry` |
| MQTT (если задан брокер) | топик `bms/dipower/telemetry` (тот же JSON, retained), `bms/dipower/status` = `online`/`offline` |

## Что известно о батарее

Из руководства пользователя (GUANGDONG DIDU NEW ENERGY, раздел 3 и 5):

- **BMS: PACE**, 16S1P, 100 А. Интерфейсы: RS485, RS232, CAN.
- RS485: **9600 бод**, 8N1; монитор — ведущий (master), батарея отвечает по адресу.
- Адрес задаётся DIP-переключателями: одиночная батарея — **адрес 1** (DIP1 = ON, остальные OFF).
- Разъём RJ45: **пин 1 (бело-оранжевый) = 485-B, пин 2 (оранжевый) = 485-A**, пины 4/5 = CAN-H/CAN-L.

У плат PACE на RS485 встречаются два протокола — зависит от прошивки BMS:

1. **Modbus RTU** (функция 0x03, регистры 0–36) — «PACE_MODBUS»;
2. **PACE ASCII v2.5** (кадры вида `~25014642E00201FD30\r`), похож на Pylontech.

Какой из них включён в вашей батарее, из документации не видно, поэтому прошивка **сама определяет**
протокол, адрес и скорость: перебирает варианты, пока BMS не ответит, и запоминает рабочий.

## Что купить

Схема подключения: [docs/wiring.svg](docs/wiring.svg).

### Вариант A — из модулей (дёшево, нужно спаять 2 резистора)

| Компонент | Ссылка | Примечание |
|---|---|---|
| ESP32 DevKit V1 (ESP-WROOM-32, 30 pin) | [arduino.ua](https://arduino.ua/prod3990-wi-fi-modyl-devkit-v1-s-esp-32) | ~295 грн; на момент проверки «очікується» — подойдёт любой аналог с [prom.ua](https://prom.ua/Wifi-esp32-wroom.html) |
| Модуль MAX485 UART↔RS485 | [arduino.ua](https://arduino.ua/prod1343-interfeisnii-modyl-max485-uart-rs485) | ~29 грн |
| Резисторы 1 кОм и 2 кОм (0.25 Вт) | любой радиомагазин | делитель 5 В → 3.3 В на линии RO |
| Патч-корд RJ45 (T568B) | любой | один конец отрезается, используются 2 жилы |
| Зарядка USB 5 В ≥ 1 А + кабель | любая | питание ESP32 |
| Провода «мама-мама» (Dupont) | любой набор | соединение модулей |

Вместо MAX485 можно взять модуль RS485 на 3.3 В с автоматическим переключением направления
(«TTL to RS485 auto direction», XY-017, на MAX3485/SP3485). Тогда делитель не нужен: VCC → 3V3,
TXD/RXD → GPIO17/GPIO16, вывод GPIO4 остаётся свободным. Если BMS не находится — поменяйте
местами RX и TX: маркировка на таких модулях бывает «от лица» микроконтроллера.

## Подключение

Вариант A:

```
ESP32 DevKit            MAX485                 RJ45 (порт RS485 батареи)
VIN (5V)  ------------- VCC
GND       ------------- GND
GPIO17    ------------- DI
GPIO4     ------------- DE и RE (соединить вместе)
GPIO16    ---+--[1 кОм]-- RO
             |
           [2 кОм]
             |
            GND
                        A  -------------------- пин 2 (оранжевый)       485-A
                        B  -------------------- пин 1 (бело-оранжевый)  485-B
```

Вариант B: клемма **A** платы → пин 2, клемма **B** → пин 1.

Важно:

- Подключайте только две жилы (пины 1 и 2). Остальные жилы патч-корда заизолируйте по отдельности:
  на пинах 4/5 этого же разъёма CAN, и лишние соединения мешают связи с инвертором.
- Перед включением прозвоните отрезанный патч-корд мультиметром: пин 1 разъёма действительно
  бело-оранжевый, пин 2 — оранжевый (у кабелей T568A цвета другие).
- На батарее несколько гнёзд RJ45. Нужен порт с подписью **RS485**. Порт, к которому подключён
  инвертор, не трогайте.
- На шине RS485 может быть только один ведущий. Если инвертор общается с батареей именно по RS485
  (а не по CAN) и свободный RS485-порт — та же самая шина, два ведущих будут мешать друг другу.
  Признак: в журнале `/log` видны «чужие» байты, опросы то проходят, то нет. Тогда варианты:
  перевести связь инвертора на CAN либо читать батарею через порт RS232.
- BMS засыпает через 24 часа без тока и без связи; регулярный опрос не даёт ей уснуть. Это немного
  увеличивает саморазряд батареи при длительном хранении.

## Прошивка

Нужен [PlatformIO](https://platformio.org/install) (расширение для VS Code или `pip install platformio`).

1. Скопируйте `include/secrets.example.h` в `include/secrets.h`, впишите имя и пароль Wi-Fi
   (и при желании адрес MQTT-брокера).
2. Подключите плату по USB и прошейте:

   ```bash
   pio run -e esp32dev -t upload
   ```

   Для LilyGO T-CAN485:

   ```bash
   pio run -e tcan485 -t upload
   ```

3. Посмотрите журнал — там будет IP-адрес и результат поиска BMS:

   ```bash
   pio device monitor
   ```

Если Wi-Fi недоступен дольше 30 секунд, устройство поднимает свою точку доступа `bms-monitor`
(пароль по умолчанию `bms-monitor`), страница — на `http://192.168.4.1/`.

Остальные настройки (адрес BMS, период опроса, номера выводов) — в [include/config.h](include/config.h).

## Формат телеметрии

`GET /api/telemetry`:

```json
{
  "online": true, "searching": false, "age_ms": 1200,
  "protocol": "modbus", "address": 1, "baud": 9600,
  "soc": 87.0, "soh": 100, "voltage": 52.80, "current": -12.34, "power": -652,
  "state": "discharging", "charging": false, "discharging": true, "eta_min": 423,
  "remaining_ah": 87.00, "full_ah": 100.00, "design_ah": 100.00, "cycles": 42,
  "cells_mv": [3300, 3301, "..."], "cell_min_mv": 3300, "cell_max_mv": 3315, "cell_delta_mv": 15,
  "temps_c": [21.5, 22.0, 21.8, 21.9], "temp_mosfet_c": 30.1, "temp_env_c": 24.0,
  "charge_fet": true, "discharge_fet": true, "current_limit": false, "heater": false,
  "fully_charged": false, "balancing_mask": 0,
  "warnings": "", "protections": "", "faults": "",
  "ok_count": 1234, "err_count": 2, "uptime_s": 6170, "rssi": -58, "ip": "192.168.1.50"
}
```

- `current` и `power`: плюс — заряд, минус — разряд. `state`: `charging` / `discharging` / `idle`.
- `online: false` — BMS не отвечает дольше 30 секунд; остальные поля тогда содержат последние
  известные значения (их возраст — `age_ms`).
- `eta_min` — оценка времени до полного заряда или до разряда при текущем токе.
- Поля, которых BMS не сообщила, равны `null`.

Пример для серверного приложения (бот в Telegram):

```bash
curl -s http://bms-monitor.local/api/telemetry
```

Через MQTT опрашивать ничего не нужно: устройство само публикует JSON после каждого опроса (раз в 5 с).

## Если BMS не находится

Откройте `http://<ip>/log` — там журнал поиска.

| В журнале | Что делать |
|---|---|
| «BMS не найдена», байтов нет вообще | Поменяйте местами A и B. Проверьте, что выбран порт RS485, а BMS включена (горит RUN). В варианте A проверьте DE+RE → GPIO4. |
| «получено N байт, не похоже на ответ» | Скорее всего перепутаны A/B (мусор) либо на шине есть другой ведущий — инвертор. |
| «BMS ответила кодом ошибки» | Связь есть, протокол ASCII; команда не поддержана этой прошивкой BMS — пришлите журнал, поправим разбор. |
| Нашлась, но цифры странные | Сравните с дисплеем батареи и пришлите `/api/telemetry` — возможна другая раскладка полей в вашей версии прошивки BMS. |

## Проверка кода

Разбор обоих протоколов вынесен в `lib/PaceBms` и покрыт тестами на ПК
(`test/host/test_protocol.cpp`), включая реальные ответы PACE BMS из открытых проектов:

```bash
c++ -std=c++17 -I lib/PaceBms test/host/test_protocol.cpp lib/PaceBms/pace_protocol.cpp -o test_protocol
```

Источники по протоколам: [syssi/esphome-pace-bms](https://github.com/syssi/esphome-pace-bms)
(карта регистров Modbus), [Tertiush/bmspace](https://github.com/Tertiush/bmspace) (ASCII-протокол).
